- 우리 프로젝트 명칭: **AniCode**
- 비교 대상: **Petchain**, **Pet-ID**
- 작성 기준:
  - 외부 서비스 설명은 2026-04-07 기준 공개 웹페이지 내용을 바탕으로 정리
  - AniCode 설명은 현재 저장소 코드(`feVite/`, `feHospital/`, `be/`, `backend/`, `bc/`) 기준으로 정리

## 1. 한 줄 요약

- **Petchain**: 블록체인 기반 반려동물 헬스케어 생태계를 표방하며, 입양·모니터링·스마트 소유권·응급 알림을 전면에 내세우는 서비스로 보인다.
- **Pet-ID**: 수의사와 보호자를 위한 **클라우드 기반 디지털 예방접종/기록 패스포트** 서비스다.
- **AniCode**: 보호자 지갑 기반 **반려동물 신원 SBT + 의료 권한 승인 + 의료 여권 + Memory NFT**를 결합한 하이브리드 Web3 서비스다.

즉,
- Petchain은 **넓은 반려동물 Web3 생태계 비전**,
- Pet-ID는 **실무형 디지털 백신/기록 관리 SaaS**,
- AniCode는 **보호자 승인 기반 의료 권한 관리와 검증 가능한 소유권 구조**에 더 강점이 있다.

## 2. 경쟁 서비스 공개 정보 요약

### 2-1. Petchain
공식 홈페이지 공개 문구 기준으로 Petchain은 자신을 **"블록체인 기반 반려동물 헬스케어 생태계"**로 소개하고 있으며, 주요 키워드로 다음을 제시한다.

- Pet Adoption
- Health Monitoring
- Smart Ownership
- Emergency Alerts
- Join Waiting List

따라서 현재 공개 정보만 기준으로 보면, Petchain은
**입양-모니터링-소유권-응급대응을 포괄하는 비교적 넓은 Web3 반려동물 플랫폼** 방향으로 보인다.  
다만 공개 페이지에서 확인 가능한 범위는 소개 문구 수준이라, 세부 권한 구조나 의료 데이터 처리 방식까지는 확정하기 어렵다.

### 2-2. Pet-ID
Pet-ID 공식 영문 페이지 기준 핵심 메시지는 다음과 같다.

- 반려동물의 **디지털 예방접종 패스포트**
- 보호자와 수의사가 **하나의 중앙 기록**을 공유
- 클라우드 기반이라 **어느 기기/브라우저에서나 접근 가능**
- PassCard를 통해 켄넬, 캐터리, 데이케어 센터 등과 기록 공유 가능
- "Created by vets, for vets"를 강하게 강조

즉 Pet-ID는 블록체인보다는 **실사용 중심의 디지털 백신/기록 관리 플랫폼**에 가깝다.

## 3. AniCode 현재 구현 요약

현재 코드 기준 AniCode는 다음 구조를 가진다.

1. **PetSBT (`bc/PetSBT.sol`)**
   - 반려동물 신원/소유권용 soulbound token
   - 보호자 지갑에 귀속

2. **MedicalPassportSBT (`bc/MedicalPassportSBT.sol`)**
   - PetSBT와 연결되는 의료 여권 SBT
   - 보호자가 병원에 기간/횟수 조건으로 권한 부여 가능
   - 병원은 승인 범위 내에서만 기록 append 가능

3. **MemoryNFT (`bc/MemoryNFT.sol`)**
   - PetSBT 보유자가 발행하는 기념 NFT
   - NFT 기반 굿즈/홀더 경험으로 연결

4. **보호자-병원 승인 UX (`be/server.js`, `feVite/src/App.jsx`, `feHospital/src/hospital.jsx`)**
   - 병원이 보호자에게 권한 요청
   - 보호자가 SSE 팝업으로 승인/거절
   - 승인 상태를 DB와 온체인 흐름에 연동

5. **오프체인 상세데이터 관리 (`be/server.js`, `backend/src/main/java/**`)**
   - 진료기록은 MySQL 저장
   - 민감 텍스트는 AES-256-CBC 암호화
   - 이미지 업로드는 S3 기반 확장 구조 존재

## 5. AniCode의 차별점

### 5-1. Pet-ID 대비 차별점
Pet-ID는 강력한 **실무형 백신/기록 클라우드** 서비스이지만, 공개 정보 기준으로는 다음 특징이 강하다.

- 중앙 클라우드 기록
- 예방접종/패스포트 중심
- 수의사 업무 효율화 중심

반면 AniCode는 다음이 차별점이다.

1. **보호자 지갑 기반 소유권**
   - AniCode는 반려동물 신원을 PetSBT로 보호자 지갑에 귀속시킨다.
   - Pet-ID는 중앙 기록 관리가 핵심이지만, AniCode는 소유권 앵커가 지갑에 있다.

2. **병원 권한을 보호자가 직접 승인**
   - AniCode는 병원이 자동 접근하지 못하고 보호자가 승인해야 한다.
   - 이 구조는 “기록을 보관하는 서비스”보다 “누가 기록에 접근할 수 있는지”를 더 강하게 통제한다.

3. **세밀한 권한 설계**
   - `MedicalPassportSBT`는 권한을 단순 허용/비허용이 아니라 **유효기간(validUntil)**, **남은 기록 횟수(remainingWrites)** 로 제어한다.
   - 이 부분은 AniCode 문서/발표에서 강한 차별 포인트가 될 수 있다.

4. **기념 자산과 서비스 혜택 연결**
   - AniCode는 의료/신원에서 끝나지 않고 MemoryNFT와 굿즈 경험까지 연결한다.
   - Pet-ID가 실무형 기록 제품이라면, AniCode는 **신원+기록+경험 자산**을 연결하는 구조다.

### 5-2. Petchain 대비 차별점
Petchain은 공개 홈페이지 기준으로 입양, 모니터링, 스마트 소유권, 응급 알림 등 **범위가 넓은 생태계형 서비스**로 보인다.  
이와 비교해 AniCode의 차별점은 다음과 같다.

1. **더 구체적인 의료 권한 모델**
   - Petchain은 broad vision 중심으로 보이지만, AniCode는 실제 코드상
     - 보호자 승인,
     - 병원 권한 요청,
     - 승인/거절,
     - 권한 기간/횟수 제한,
     - 의료 기록 append
     흐름이 더 구체적으로 구현돼 있다.

2. **병원-보호자 양측 UI가 분리되어 있음**
   - AniCode는 보호자용(`feVite`)과 병원용(`feHospital`) 인터페이스가 분리되어 있다.
   - 이는 단순히 “헬스케어 생태계”를 말하는 수준이 아니라 실제 운영 역할을 분리한 구조다.

3. **온체인과 오프체인의 역할 분리가 명확함**
   - AniCode는 신원/권한/기록 앵커는 온체인,
   - 민감 상세 내용은 암호화 후 오프체인 저장이라는 하이브리드 구조를 채택한다.
   - 이 점은 실제 서비스 운영 관점에서 현실적이다.

4. **의료 신뢰성과 감성 자산을 동시에 연결**
   - Petchain이 입양/웨어러블/응급 쪽으로 넓게 펼쳐진다면,
   - AniCode는 **의료 권한 신뢰 구조 + MemoryNFT**라는 조합으로 더 선명한 콘셉트를 만들 수 있다.

## 6. 발표/문서에서 써먹기 좋은 차별화 문장

### 버전 A: 가장 직관적인 문장
> **Pet-ID가 중앙 클라우드형 디지털 백신수첩이라면, AniCode는 보호자 지갑 기반으로 의료 접근 권한까지 통제하는 검증 가능한 반려동물 신원·의료 플랫폼이다.**

### 버전 B: Petchain과 대비하는 문장
> **Petchain이 넓은 반려동물 Web3 생태계를 지향한다면, AniCode는 병원 권한 승인과 의료 기록 무결성에 집중한 실사용형 의료 신뢰 레이어를 지향한다.**

### 버전 C: 우리 서비스 정의 문장
> **AniCode는 반려동물의 소유권, 의료 접근 권한, 기념 자산을 하나의 지갑 중심 구조로 연결하는 하이브리드 Web3 서비스다.**

## 7. 우리 팀이 강조해야 할 포인트

### 7-1. 반드시 강조할 것
1. **보호자 승인 기반 권한관리**
2. **병원 권한의 기간/횟수 제한 가능**
3. **의료 기록의 온체인 앵커 + 오프체인 암호화 저장**
4. **PetSBT / MedicalPassportSBT / MemoryNFT 역할 분리**
5. **의료 신뢰성과 NFT 경험을 함께 가져가는 구조**

### 7-2. 과장하면 안 되는 것
1. **입양 플랫폼**: 현재 AniCode 핵심 구현이 아님
2. **웨어러블 건강 모니터링**: 현재 코드에 없음
3. **완전한 의료 기록 표준화 완료**: 아직 아님
4. **완전한 오프체인 접근통제 완성**: 추가 보완 필요

즉, AniCode는 Petchain처럼 너무 넓게 말하기보다,
**“반려동물 의료 권한과 신원 검증에 집중된 서비스”**로 잡는 편이 훨씬 강하다.

## 8. 네이밍 변경 반영 제안

앞으로 외부 문서에서는 서비스명을 **PetChain**보다 **AniCode**로 통일하는 것이 좋다.

### 권장 표현
- 서비스명: **AniCode**
- 설명 문장 예시:
  - **AniCode는 반려동물의 identity를 기록하고, 의료 접근 권한을 코드처럼 명확하게 관리하는 서비스입니다.**
  - **AniCode = Animal + Identity + Code**

### 네이밍 변경의 장점
1. **경쟁 서비스 Petchain과 직접 이름이 겹치지 않음**
2. 단순 체인 강조보다 **정체성(identity) + 권한 규칙(code)** 이미지를 줄 수 있음
3. 발표 때 “왜 Web3를 쓰는가”를 기능적으로 설명하기 쉬움

## 9. 결론

현재 공개 정보 기준으로 정리하면,

- **Petchain**은 넓은 Web3 반려동물 생태계 비전형 서비스
- **Pet-ID**는 중앙 클라우드형 디지털 예방접종/기록 관리 서비스
- **AniCode**는 보호자 지갑 기반 신원과 의료 권한 통제를 결합한 하이브리드 Web3 서비스

따라서 AniCode의 가장 강한 차별점은 아래 한 문장으로 요약할 수 있다.

> **AniCode는 단순히 반려동물 정보를 저장하는 서비스가 아니라, 보호자가 병원 접근 권한을 직접 승인하고 검증 가능한 방식으로 관리하는 반려동물 의료 신뢰 인프라다.**
