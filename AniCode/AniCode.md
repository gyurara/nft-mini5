  
5조 기획서

1. 서비스 개요

\-서비스명: petchain  
\-팀명: 5조  
\-기존의 문제: 기존에는 병원 간 데이터 연동이 이루어지지 않아,  
새로운 병원을 방문할 경우 과거 진료기록을 즉시 조회하기 어렵고  
보호자가 직접 설명하거나 별도의 서류를 제출해야 하는 불편이 존재 \+ 보험 가입 시 과거 병력 증빙이 어려워 보장 제외 또는 보험료 상승 등의 불이익이 발생할 수 있음

\-해결하려는 문제: 파편화된 반려동물 의료 데이터를 오프체인에 저장하고,  
해당 데이터의 해시값과 검증 상태를 블록체인에 기록함으로써  
데이터의 위변조를 방지하고 신뢰 가능한 의료 이력 증명 구조를 구축한다.

이를 통해 병원에서는 별도의 서류 제출 없이  
신뢰 가능한 과거 진료 이력을 빠르게 확인할 수 있으며,  
보험사 또한 검증된 의료 데이터를 기반으로  
정확한 심사 및 상품 제공이 가능하도록 한다.

2. web 2방식의 구조  
1) 기존 서비스 흐름 (Web 2\)

\-데이터 저장 방식: 데이터베이스 저장  
\-신뢰구조 : 병원 및 서비스 운영자의 내부 시스템과 권한 관리에 의존  
\-운영주체 : 각 병원 또는 플랫폼 사업자

2) 기존 한계

\-위변조 가능성: 중앙 운영자 또는 내부 권한에 의해 데이터 변경 가능 (외부 검증 어려움)  
\-소유권문제: 데이터가 병원 시스템에 종속되어 보호자가 직접 통제하기 어려움  
\-중앙화문제: 병원 간 데이터 표준 및 연동이 부족하여 이력 공유가 어려움  
\-기타: 병원 변경 시 기록 전달을 위한 별도 서류 발급 및 제출 필요

3. Rebuild설계 개요

1) SBT의 역할

\-자산: 반려동물의 신분증을 사용자가 입력  // 권한 설정, 어떻게 발행할 지   
\-인증: 특정 의료 행위(중성화, 예방접종 등)의 완료를 병원이 증명 //인증 권한 자세히 정리  
\-멤버십 : 보호자-반려동물 관계 기반 서비스 접근 권한 제공   
\-기타 : 생애 기록 기반 기념 토큰

최종 설명: 본 서비스에서 SBT는 (반려동물의 신원 인증) 역할을 하며 (병원진료)상황에서 사용된다

2) NFT의 역할

\-자산: 고객에게 부여되는 디지털 권한 자산으로, 서비스 내에서 사용 가능한 혜택 단위  
\-인증: 특정 조건 또는 상태 충족 여부를 증명하는 토큰  
\-멤버십 : 특정 기능 또는 서비스 접근 권한을 부여하는 수단  
\-기타 :  이벤트, 보상, 조건 달성 시 발급되는 단발성 사용 토큰

최종 설명: 본 서비스에서 NFT는 (사용자에게 귀속되는 비거래형 유틸리티 토큰 ) 역할을 하며   
(특정 조건 충족을 증명하고 서비스 내 혜택을 사용하는 ) 상황에서 사용된다

3) Token Lifecycle

\-Mint: 고객이 반려동물 sbt를 민팅  
\-owner: 고객  
\-Transfer: 불가능(단, 필요 시 관리자에 의한 예외적 재발급 또는 소유자 재지정 정책 고려 가능)  
\-Use: 반려동물의 이력 확인  
\-Burn/Expire: 일반적으로 소멸되지 않으며, 필요시 관리자나 유저가 상태 비활성화

\-Mint: 조건 충족 시 NFT 발급 (이벤트, 구매, 보상 등)  
\-owner: 고객  
\-Transfer: 불가능-특정 사용자에게 귀속되는 쿠폰형 NFT  
\-Use: 서비스 내에서 혜택 사용(할인, 이용권, 인증 등)  
\-Burn/Expire : 사용 시 소각(Burn) 또는 기간 만료(Expire) 처리

4) 블록체인의 필요성

본 서비스는 (  신뢰 가능한 이력 증명  )을 이유로 블록체인을 사용한다.  
기존 DB방식과 비교했을 때 ( 제3자(병원, 보험사 등) )도  
( 신뢰할 수 있는 검증 가능한 기록을 확인할 수 있다 )점에서 차별성이 있다.

UI\< \-  \>블록체인 연결  
 반려동물 등록 및 SBT 발급

- 사용자 행동 :  반려동물 이름·종·생년월일·이미지를 입력하고 SBT 발급하기 버튼을 클릭  
- 호출함수 : registerPet  
- 블록체인 기록 : 보호자 지갑 주소, 토큰 ID, 메타데이터 URI, 발급 시각  
- 결과: 사용자가  SBT 발급하기를 실행하면 registerPet함수가 호출되고 블록체인에는 보호자 지갑 주소등이 기록되며 결과적으로 SBT가 귀속된 상태가 된다.


병원 승인

- 사용자 행동 :  병원으로부터 받은 지갑 주소를 입력하고 병원 승인 버튼을 클릭  
- 호출함수 : approveVet  
- 블록체인 기록 :  petSbtId, 승인된 병원 지갑 주소, 승인 시각  
- 결과: 사용자가  병원 승인을 실행하면 approveVet 함수가 호출되고 블록체인에는 승인된 병원 지갑 주소등이 기록되며 결과적으로 해당 병원이 진료기록을 추가·조회할 수 있는 승인 상태가 된다.


기념 NFT 발행

- 사용자 행동 :  예방접종 완료, 생일, 입양 기념일 등 이벤트를 선택하고 NFT 발행 버튼을 클릭  
- 호출함수 : mintMemoryNFT  
- 블록체인 기록 :  NFT tokenId, petSbtId, 소유자 주소, tokenURI, 지불 금액, 발행 시각  
  결과: 사용자가  NFT 발행을 실행하면 mintMemoryNFT함수가 호출되고 블록체인에는 기념 NFT등이 기록되며 결과적으로 이벤트가 거래 가능한 디지털 자산으로 보호자 지갑에 귀속된 상태가 된다.

\<권한관리\>  
누가 실행 가능한가 : 보호자(SBT 소유자), 승인된 병원, 서비스 운영자

제한 조건 : ownerOf(tokenId) \== msg.sender 조건으로 보호자 여부를 검증하고, approvedVets\[petSbtId\]\[msg.sender\] \== true 조건으로 병원 승인 여부를 검증 한다  
추가로 SBT는 전송이 차단되어 있어 소유권 자체를 이전하거나 위임하는 것은 불가능

관리자 역할 : 컨트랙트 배포자만 setMintPrice(), withdraw() 를 실행할 수 있다.

\<트랙잭션 및 비용\>  
트랜잭션 발생 여부 : 상태를 변경하는 쓰기 작업(SBT 발급, 병원 승인, 기록 추가, 정보 수정)시 트랜잭션이 발생

가스비 발생여부 :  SBT 발급과 정보 수정은 보호자가 가스비를 부담한다. 기록 추가는 병원이 부담하거나 서비스가 대납하는 구조로 한다.

의료비 부담이 기록 수요를 만든다 반려가구 34.4%가 정기 건강검진을 하고, 최근 2년 평균 치료비는 146만 원(치료 경험 가구 기준), 100만 원 이상 지출 가구가 26.2%입니다. 의료비가 클수록 기록·비교·증빙 도구의 필요성이 높아집니다.

보험 시장은 초기 단계, 성장 여지가 크다 펫보험 인지도는 91.7%인데 실제 가입률은 약 1.7%에 불과합니다. 관심은 높지만 시장이 아직 초기라는 뜻이며, 금융위도 진료·등록·보험·청구를 원스톱 연결하는 방향을 정책으로 제시했습니다.

진짜 빈틈은 "기록이 없어서"가 아니라 "흩어져 있어서"입니다. 기록은 병원 EMR·영수증·앱·보호자 메모로 분산되어 있고, 표준화와 접근권이 없습니다. 보험연구원은 진료항목 표준화와 기록 공개가 펫보험 활성화의 핵심 과제라고 지적했고, 현행 수의사법에는 보호자 대상 진료기록 제출 의무 자체가 없습니다.
